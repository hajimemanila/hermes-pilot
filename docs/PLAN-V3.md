# PWA の役割を絞った仕様提案（2026-10-23）

前提（決定済み）:
- 指示は Discord、詳細確認は標準ダッシュボード（9119）
- この PWA は **「どちらかを開くまでもない操作・確認」だけ**を数秒で処理する
- インフラ即応ボタンの拡充（SecurityAgent / キャッシュ掃除）と Web Push は**見送り**

本文書は提案のみ。実装は未着手。

---

## 1. 採用判定の基準

提案は次の4条件で絞った。

1. **1〜2タップで完結**する（Discord に戻る／ダッシュボードを開くより速い）
2. **答えが1画面で出る**（詳細画面へ遷移しない）
3. 書き込みを伴う場合、**冪等・取り消せる・被害が小さい**
4. **既存機能と重複しない**（重複するなら置き換える）

## 3. 提案（優先順）

### ★★★ A. 横断検索「あの話どこだっけ」

- **何を**: 全セッション（Discord / CLI / カンバン）の発言を1つの検索窓から引き、ヒットした会話へ飛ぶ
- **なぜ PWA か**: Discord はスレッドを跨いだ検索が弱く、ダッシュボードはセッションを開いてから探す。スマホでは「3秒で見つける」が価値
- **実測**: 8,385件で 0.2〜1.4ms、trigram なので日本語の部分一致も効く
- **設計**: `GET /api/search?q=&limit=30` → `messages_fts_trigram` を JOIN して `{session, role, snippet, at, discordUrl}` を返す。タップで該当セッションを resume して該当箇所までスクロール
- **重複**: なし（現状の PWA に検索は無い）
- **規模**: 0.6日（API 0.2 / UI 0.3 / テスト 0.1）

### ★★★ B. クイック起票（音声入力つき）

- **何を**: 1行書く／話すだけでカンバンにタスクを作る（ボード・優先度・担当をその場で選ぶ）
- **なぜ PWA か**: 「思いついた瞬間」に Discord で長文を書くのは重い。移動中に3タップで起票したい
- **設計**: `POST /api/boards/:slug/tasks` → `hermes kanban create --json`（CLI 経由。DB 直接書き込みはしない）。`X-Client` と監査ログ、レート制限、`idempotency-key` で二重起票防止
- **音声**: `webkitSpeechRecognition`（Android Chrome）。失敗時はキーボードに落ちる
- **重複**: Discord からの起票と重なるが、**入力手段の違い**（移動中・短時間）。起票後の編集は Discord / ダッシュボードに任せる
- **規模**: 0.7日

### ★★ C. 今日のコスト・トークン

- **何を**: 直近24時間の in/out/cache/コストと、モデル別内訳を1画面で
- **なぜ PWA か**: 「今いくら使った？」は毎日見るが、ダッシュボードを開くほどではない
- **実測**: `sessions` + `session_model_usage` の集計は **0.0ms**
- **設計**: `GET /api/usage?hours=24` → 集計のみ返す（本文は返さない）。タスクタブ上部の `strip` に「$1.61 / cache 98%」を追加
- **重複**: ダッシュボードの使用量画面と重なるが、**粒度が違う**（1行サマリ vs 明細）
- **規模**: 0.3日

### ★★ D. ワンタップ一時停止（pause / resume）

- **何を**: 「新しい仕事を止める」だけの1ボタン。実行中のターンは完走する
- **なぜ PWA か**: 外出先で「まず止めたい」とき、drain→restart はやり過ぎ。`hermes pause` が正解の操作
- **設計**: `POST /api/gateway/pause` / `resume` → `hermes pause --reason "mobile"`。緊急操作シートに「一時停止（新規のみ）」を追加。既存の drain/restart/stop は残す
- **重複**: 既存キルスイッチと近いが、**意味が違う**（停止 vs 再起動）。追加であり置換ではない
- **規模**: 0.3日

### ★★ E. いま動いているもの（ライブ進捗）

- **何を**: 「Discord で投げた依頼が今どこまで進んだか」を1画面で。実行中ターン・経過時間・最後のツール名・実行中タスク
- **なぜ PWA か**: Discord に戻ってログを追うのが一番重い。進捗だけ見たい場面が多い
- **実測**: `session_turn_leases` に実行中セッションと期限が入っている（実測1件）
- **設計**: `GET /api/live` → leases + `sessions.last_activity_description` + カンバン running を合成。5秒ポーリング（既存のタスクと同じ間隔）
- **重複**: ダッシュボードの実行中表示と重なるが、**スマホで1画面**という点が違う
- **規模**: 0.5日

### ★★ F. 承認待ちインボックス

- **何を**: `blocked` / `needs_input` のタスクを一覧し、**質問を読んでコメントで答える**だけ
- **なぜ PWA か**: 「何を聞かれているか」を確認して一言返すのは、スマホで完結できる
- **設計**: `GET /api/inbox`（blocked タスク + 最後のコメント）+ `POST /api/boards/:slug/tasks/:id/comment`（`hermes kanban comment`）。**ステータス変更はさせない**（再開は Discord / ダッシュボード）
- **重複**: タスクタブの詳細と重なるが、**横断の受信箱**が新しい
- **規模**: 0.5日

### ★ G. 成果物ビューア

- **何を**: チャットの添付画像・生成されたドキュメントを PWA 内で開く／共有
- **なぜ PWA か**: 「さっき作った資料を確認」はスマホで済ませたい
- **設計**: 既存の `@file:` 参照をパス解決して `GET /api/files?path=` で返す（**許可ディレクトリ限定**、`~/.hermes/attachments`, 選択中ボードの repo 配下）
- **重複**: ダッシュボードのセッション添付と重なる
- **規模**: 0.6日（サンドボックス設計込み）

### ★ H. ダッシュボード深リンク

- **何を**: 詳細を見たいとき、該当ページ（セッション・プラグイン）へ1タップで飛ぶ
- **なぜ PWA か**: 「ここから先は本家で」の動線を切らない
- **設計**: セッション／タスクに `dashboardUrl` を持たせて `window.open`。実装ほぼ0
- **規模**: 0.1日

### ★★ I. タブレット 2ペイン

- **何を**: 幅 ≥ 820px で「一覧 | 詳細」の2ペイン。スマホは現状維持
- **なぜ PWA か**: タブレットは画面が広く、シートを開くたびに一覧が隠れるのは損
- **設計**: `@media (min-width: 820px)` でグリッド化。状態は既存の `detail` を右ペインに流すだけ
- **規模**: 0.8日

## 4. 見送り（理由つき）

| 案 | 理由 |
| --- | --- |
| Web Push / インフラ即応ボタン | 決定済み（頻度が低い） |
| モデル・MoA の切替 | 誤操作の影響が大きく、Discord 指示で足りる |
| バックアップ / ロールバック | 不可逆。失敗時の被害が大きすぎる |
| ファイル編集 | エディタは PC。閲覧（G）までに留める |
| cron の即時実行 | 月数回。`hermes cron run` をターミナルの定型に足せば足りる |
| 通知（バッジ以外） | 見送り決定済み。実行中数のバッジで代替 |

## 5. ロードマップ案

| バッチ | 内容 | 工数 | 期待効果 |
| --- | --- | --- | --- |
| A | 横断検索 + コスト + ダッシュボード深リンク | 1.0日 | 「探す・確認する」が PC 不要になる |
| B | クイック起票 + 一時停止 | 1.0日 | 「思いついた／止めたい」が3タップ |
| C | ライブ進捗 + 承認待ち + 成果物ビューア | 1.6日 | Discord に戻る回数が減る |
| D | タブレット 2ペイン | 0.8日 | タブレットでの確認が速い |

推奨は **A → B →（C は必要になった順に）**。A だけで「スマホで完結する確認」の大半が成立する。

### 実装時に守る既存の原則
- 読み取りは SQLite を `readOnly` で開く（WAL なので安全）
- 書き込みは CLI（`hermes kanban …` / `hermes pause`）経由。DB 直接書き込みはしない
- すべて `X-Client: mobile` + レート制限 + 監査ログ
- 既存ダッシュボード（9119）と DSH（8787）は変更しない
