# PLAN-V4: ボード選択 UI の評価（実装前の比較）

対象: タスクタブ上部のプロジェクト（ボード）選択。スマホ縦使いでの操作性。

## 実測した現状（390×844 / 9ボード）

| 項目 | 実測値 |
| --- | --- |
| チップ列の高さ | 38px |
| チップの総幅 | **1,633px** / 表示 366px = **4.5画面分** |
| 1画面に見えるチップ | 約2個（幅 134〜237px） |
| タスク一覧の高さ | **670px** |
| 一覧の他の帯 | header 46 / 統計タイル 51 / list-head 42 / 緊急操作 49 |

→ 遠いボードに切り替えるには**横スワイプを数回**。名前は全部見えるが、探すのに時間がかかる。

## 案の比較

| | A. チップ + 「▾」で全ボードのシート | B. 5行リスト（提案） | C. 2行折返し |
| --- | --- | --- | --- |
| 常時の高さ | **±0px** | **+194px**（34px×5行+gap） | +76px |
| タスク一覧の残り | 670px（不変） | **476px（−29%）** | 594px |
| 全ボードを見る操作 | 1タップ→全9件が**スクロール無し**で見える | 1タップ→5件、残り4件はスワイプ | 1タップ→4件、残り5件はスワイプ |
| 切り替えの手数 | 2タップ | 1タップ | 2タップ（スクロール＋タップ） |
| 名前の見え方 | フル表示 | フル表示 | チップ幅で切れない |
| 実装コスト | **1.0h**（`.list-item` と既存シートを再利用） | 2.5h（設定・保存・スワイプ・テスト） | 1.5h |
| タブレット | 影響なし | 邪魔（設定でオフ前提） | 邪魔 |

## 評価

- **B（5行リスト）は「探す」問題を解決するが、代償が大きい。** 常時 194px を失い、
  タスク一覧が 670px → 476px（−29%）。一覧は1画面に4〜5件しか載らなくなる。
  さらに 9 ボードに対して5行なので**スワイプが必要**な点は A と同じ。
- **A（▾シート）は 0px で同じ「探す」問題を解く。** 9件 × 46px = 414px で
  **1画面に全部入る**（スワイプ不要）。既存のシート/`.list-item` をそのまま使える。
- **B が効くのは「ボードを頻繁に切り替える人」**。常時見えていること自体に価値があるケース。
  その場合は既定オフの表示オプションとして持つのが妥当（スマホ縦のみ自動 ON は、
  一覧を 29% 削る判断を利用者に代わってやってしまうので採らない）。

## 推奨

1. **まず A を実装**（1.0h）。チップ列の左端に「▾」、押すと全ボードのシート。0px・1タップ。
2. **B は設定オプションとして追加**（2.5h）。`設定 → ボード選択: チップ / 5行リスト`、
   `localStorage['hm.boardView']`、既定はチップ。5行は34px のコンパクト行にして
   `.list-item`（46px）の 5 行 = 230px にはしない。
3. C は採らない（中途半端。A で足りる）。
